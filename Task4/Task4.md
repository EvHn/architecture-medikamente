
### Приоритизация

| Приоритет | Мера по устранению | Целевая категория проблем | Ожидаемый результат |
| :-------- | :--- | :--- | :--- |
| **🔴 Высокий** | **1. Инвентаризация и классификация данных** <br>Необходимо вручную или с помощью скриптов разобрать файловую свалку, отделить ПДн от административных файлов и составить реестр. | Данные, Окружение |  Опредение объема и структуры данных, необходимое для проектирования новых БД и контуров безопасности. |
| **🔴 Высокий** | **2. Внедрение паттерна Strangler Fig** <br>Не переписывать всё сразу. Разместить API Gateway перед монолитом. Новые функции (например, запись на прием онлайн) реализовывать как отдельный микросервис, постепенно отключая старый код. | Процессы, Персонал | Снижение рисков отказа всей системы, плавный переход, возможность отката, время на обучение персонала и снижение сопротивления |
| **🔴 Высокий** | **3. Создание изолированной тестовой среды** <br>Перед миграцией продуктивных данных необходимо проверить ETL-процессы на копии данных. | Инфраструктура, Контроль | Выявление скрытых дефектов данных и падения производительности до их появления в бою. |
| **🟡 Средний** | **4. Обучение персонала и вовлечение ключевых пользователей** <br>Провести серию демонстраций и сбор обратной связи от врачей и администраторов на ранних этапах прототипирования интерфейсов. | Персонал | Снижение сопротивления, выявление реальных сценариев использования, зашитых в старом поведении. |
| **🟡 Средний** | **4. Найм новый сотрудников с нужными компетенциями** <br>Поиск новых людей с конметенциями для создания и поддержки приложения и новой инфраструктуры. | Инфраструктура, Персонал | Закрытие пробелов в компетенциях |
| **🟡 Средний** | **5. Разработка схемы ETL с учетом Privacy by Design** <br>При выгрузке данных из файлов в новые БД сразу применять токенизацию идентификаторов и разделять хранилища: одно для клиники (с ПДн), другое для аналитики (обезличенное). | Данные, Окружение | Соответствие регуляторным требованиям |
| **🟡 Средний** | **6. Внедрение централизованного логирования и трейсинга (Observability)** <br>С первого запуска первого микросервиса настроить отправку логов в общее хранилище (например, OpenSearch) и трассировку запросов (Jaeger/Zipkin). | Контроль, Инфраструктура | Возможность быстрого поиска причин ошибок в распределенной системе, что критически важно на этапе становления новой архитектуры. |
| **🟢 Низкий** | **7. Автоматизация бэкапов новых баз данных** <br>Внедрение утилит для point-in-time recovery (PITR) для PostgreSQL или аналогичных для выбранной СУБД. | Процессы, Инфраструктура | Гарантия восстановления данных после неизбежных ошибок при настройке миграции. |
| **🟢 Низкий** | **8. Документирование API контрактов (OpenAPI/Swagger)** <br>Перед релизом каждого сервиса готовить спецификацию для облегчения будущей интеграции и тестирования. | Методы | Упрощение поддержки системы после ухода команды внедрения. |
